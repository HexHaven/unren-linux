# i18n (Milestone 5)

`src/unren/ui/i18n.py` provides translation loading + lookup for the
interactive menu (`ui/interactive.py`) and the CLI (`unren.cli`).

## Using it

```python
from unren.ui.i18n import t

print(t("menu.title"))
print(t("error.path_not_found", message=exc.message))
```

`t(key, **kwargs)` always returns a string and never raises. `**kwargs`
fill `str.format` placeholders (`{name}`) in the translated text.

Call `i18n.configure(cli_language=args.language, config_language=cfg.language)`
once at CLI startup (in `unren.cli.main`, after argument parsing and config
loading) so the rest of the process uses the resolved language. If nothing
calls `configure()`, `t()` lazily configures itself with no CLI/config
override (env var / default `en` only) the first time it's called.

## Language detection order

1. explicit `--language` CLI flag
2. `UNREN_LANGUAGE` / `LC_LANG` / `LC_ALL` / `LANG` env var (first one set wins)
3. `language` key in the loaded `UnrenConfig` (`unren.toml`)
4. default: `en`

## Locale files

`src/unren/locales/{en,de}.json` — flat JSON objects (`"dotted.key": "text"`).
`en.json` is the required fallback and must be complete; `de.json` (and any
future locale) must define the exact same key set — enforced by
`tests/unit/test_i18n.py::test_shipped_en_and_de_have_identical_key_sets`.

Missing-key fallback: selected language -> `en` -> the raw key string itself
(never raises, never silently disappears).

## Key namespaces (coordinate new keys here — don't invent parallel schemes)

- `menu.*` — interactive menu strings
  - `menu.option.<name>` — one-line menu entry label (mirrors a CLI subcommand
    name, e.g. `menu.option.extract` <-> `unren extract`)
  - `menu.description.<name>` — longer help text for that same action
  - `menu.prompt.*`, `menu.invalid_*`, `menu.goodbye`, `menu.back`, `menu.quit`
    — menu-loop chrome
- `cli.*` — generic CLI status/confirmation messages
- `error.*` — one key per `UnrenError.code`, with dashes -> underscores
  (`missing-game-directory` -> `error.missing_game_directory`); all take a
  `message={exc.message}` kwarg.

When the menu/CLI tasks need a new user-facing string, add the same key to
*both* `en.json` and `de.json` in the same change; the coverage test fails
the build otherwise.
